## Managing the local server

Use `yarn searm docker:*` to control the local SeaRM container:

| Command | What it does |
|---------|--------------|
| `yarn searm docker:start` | Start the server (pulls the image if needed) |
| `yarn searm docker:start 2.2.0` | Start a specific server version |
| `yarn searm docker:start --port 3030` | Start on a custom port |
| `yarn searm docker:stop` | Stop the server (preserves data) |
| `yarn searm docker:status` | Show URL, version, and login credentials |
| `yarn searm docker:logs` | Stream server logs |
| `yarn searm docker:reset` | Wipe data and start fresh |
| `yarn searm docker:upgrade` | Pull the latest `searm-app-dev` image |
| `yarn searm docker:upgrade 2.2.0` | Upgrade to a specific version |

Data persists across restarts in two Docker volumes (`searm-app-dev-data` for PostgreSQL, `searm-app-dev-storage` for files). Use `reset` to wipe everything.

## Pinning the server version

When no version is passed, `docker:start` resolves the version from your app's `engines.searm` range in `package.json` — the same range the server validates against when your app is installed. It starts the newest published `searm-app-dev` image that satisfies the range, falling back to `latest` when the field is absent or no published version matches:

```json filename="package.json"
{
  "engines": {
    "searm": ">=2.2.0"
  }
}
```

Pass a version explicitly to override the range for a single run: `yarn searm docker:start 2.3.0`. If a container already exists on a different version, `docker:start` upgrades it in place (recreating the container while preserving your data volumes).

## Upgrading the server image

`yarn searm docker:upgrade` pulls the latest image, compares digests, and only recreates the container if anything actually changed. Volumes are preserved — only the container is replaced. If a new image was pulled and the container was running, the upgrade automatically starts a new container; run `yarn searm docker:start` afterward to wait for it to become healthy.

```bash filename="Terminal"
yarn searm docker:upgrade            # Latest
yarn searm docker:upgrade 2.2.0      # Specific version
```

Verify the running version with `yarn searm docker:status` (it shows the `APP_VERSION` baked into the container).

## Running a parallel test instance

Pass `--test` to any `docker:*` command to manage a second, fully isolated instance — useful for integration tests or experiments without touching your main dev data:

| Command | What it does |
|---------|--------------|
| `yarn searm docker:start --test` | Start the test instance (defaults to port 2021) |
| `yarn searm docker:stop --test` | Stop it |
| `yarn searm docker:status --test` | Show its status |
| `yarn searm docker:logs --test` | Stream its logs |
| `yarn searm docker:reset --test` | Wipe its data |
| `yarn searm docker:upgrade --test` | Upgrade its image |

The test instance has its own container (`searm-app-dev-test`), volumes (`searm-app-dev-test-data`, `searm-app-dev-test-storage`), and config — it runs alongside your main instance without conflicts. Combine `--test` with `--port` to override 2021.

## Manual setup (without the scaffolder)

Skip the scaffolder if you're adding the SDK to an existing project:

```bash filename="Terminal"
yarn add searm-sdk searm-client-sdk
```

Add the script to `package.json`:

```json filename="package.json"
{
  "scripts": {
    "searm": "searm"
  }
}
```

You can now run `yarn searm dev`, `yarn searm docker:start`, and the rest.

<Note>
Don't install `searm-sdk` globally — pin it per project so each app uses its own version.
</Note>
