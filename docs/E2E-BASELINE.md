## Prioritized fix list for a single login → view → edit round trip

1. **`packages/twenty-server/src/engine/core-modules/usage/usage.resolver.ts:22`** — change `@Args() input: UsageAnalyticsInput` to `@Args('input') input: UsageAnalyticsInput` (or change `UsageAnalyticsInput` from `@InputType()` to `@ArgsType()` at `packages/twenty-server/src/engine/core-modules/usage/dtos/inputs/usage-analytics.input.ts:8` and drop the wrapper Args name). Without this the GraphQL schema never builds and the server cannot start at all — this is the single highest-priority blocker for the whole stack. Re-check first, since it sits in the usage-ledger area another agent is actively rewriting; may already be fixed by the time this is read.
2. **`packages/twenty-sdk/package.json`** prebuild script for `twenty-sdk:build` — the `rimraf 'dist/sdk' 'dist/define/**/*.d.ts' ...` invocation with single-quoted globs is not portable to this Windows/Git-Bash/npm-exec setup and hard-fails the entire `twenty-front` dependency graph before Vite even starts. Needs either double-quoting, a cross-platform glob-quoting approach, or switching to rimraf's programmatic API / a small Node script, so `nx start twenty-front` can get past its own dependency build on Windows.
3. Once (1) and (2) are fixed, re-run this whole sequence for a true first boot: server → worker → frontend → the six-step browser round trip → `bash scripts/lowmem.sh itest`. None of steps 3–7 above have ever actually been observed to pass; this document only establishes that the infra and DB layers are sound and pins the first two hard blockers precisely.
4. Environment note (not a code fix, but will re-trip future agents on this box): the global `yarn` shim at `C:\Users\Vatsa\AppData\Roaming\npm\node_modules\yarn\bin\yarn.js` is broken/missing, which breaks any npm script that shells out to `yarn` (e.g. `database:init:prod`'s `... && yarn database:migrate:prod`). Worked around here by calling `node dist/command/command run-instance-commands` directly; worth fixing the yarn install or routing these scripts through the already-invoked package manager instead of hardcoding `yarn`.
